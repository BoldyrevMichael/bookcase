# Локальный стенд

База, брокер, объектное хранилище, вход по учётной записи и наблюдаемость —
всё окружение сервисов. Сами сервисы поднимаются отдельным профилем.

## Запуск

```bash
cp .env.example .env
docker compose up -d
```

Первый запуск с нуля занимает около минуты. Разовые контейнеры `kafka-topics`
и `seaweedfs-buckets` отрабатывают и завершаются с кодом 0 — так и должно быть.

Вместе с сервисами:

```bash
cd ../.. && ./gradlew assemble && cd deploy/compose
docker compose --profile services up -d
```

Собранный jar подключается томом и запускается в базовом образе JRE — правка
кода стоит `./gradlew bootJar` и перезапуска контейнера, без сборки образа.
Свой образ у каждого сервиса появится вместе с выкатом в кластер.

Сервис можно запустить и прямо на машине — так удобнее отлаживать:

```bash
./gradlew :services:catalog:bootRun
```

Тогда в `.env` нужно переписать список адресов, по которым шлюз ищет API,
заменив имя контейнера на `host.docker.internal`:

```properties
API_UPSTREAMS=http://host.docker.internal:8080/api/v1/,static://200
```

На Linux с включённым брандмауэром обращения из контейнеров к машине по
умолчанию отбрасываются — понадобится разрешить входящие с моста `docker0`.

Остановить, сохранив данные:

```bash
docker compose down
```

Остановить и стереть данные (базы, топики, объекты — всё заводится заново
при следующем запуске):

```bash
docker compose down -v
```

## Что где

| Что | Адрес | Учётная запись |
|---|---|---|
| Вход в систему (BFF) | http://localhost:4180 | `reader` / `reader`, `neighbour` / `neighbour` |
| Keycloak | http://localhost:8180 | `admin` / `admin` |
| PostgreSQL | localhost:5432 | базы `catalog`, `storage`, `ingester`, `enricher`, `keycloak` |
| Kafka | localhost:29092 | — |
| SeaweedFS (S3) | http://localhost:8333 | `storage` / `storage-secret` |
| SeaweedFS (состояние) | http://localhost:9333 | — |
| Prometheus | http://localhost:9090 | — |
| Grafana | http://localhost:3000 | `admin` / `admin` |
| Tempo | http://localhost:3200 | — |

Порты публикуются только на `127.0.0.1`: стенд не должен оказаться в сети
по недосмотру. Все учётные записи здесь заведомо тестовые и годятся только
для машины разработчика.

**Стенд открывается по имени `localhost`, а не по `127.0.0.1`.** Адрес возврата
после входа и издатель токена заданы через `localhost`, и обращение по другому
имени узла оборвёт вход.

## Как получить токен

Программные клиенты ходят с Bearer-токеном мимо сессии браузера. Токен берётся
у тестового клиента прямым обменом логина:

```bash
curl -s -X POST http://localhost:8180/realms/bookcase/protocol/openid-connect/token \
  -d grant_type=password \
  -d client_id=bookcase-test -d client_secret=local-dev-test-secret \
  -d username=reader -d password=reader
```

В realm заведён и клиент `bookcase-foreign` — он выдаёт токен без нужного
получателя (`aud`). Такой токен обязан получать 401: это отрицательная проверка,
а не запасной способ входа.

## Устройство

**PostgreSQL** — одна СУБД, но своя база и своя роль у каждого сервиса. Роль
не имеет права подключиться к чужой базе, так что сервис не дотянется до чужих
таблиц даже по ошибке в настройках. В базе `catalog` заранее поставлены
расширения `pg_trgm` и `unaccent` — на них опирается поиск.

**Kafka** работает в режиме KRaft, топики заводятся явно скриптом
`kafka/create-topics.sh`; автосоздание у брокера выключено, чтобы опечатка
в имени кончалась ошибкой. Там же расписано, откуда берутся топики повторов
и отказов и почему их имена содержат имя потребителя.

**SeaweedFS** отдаёт S3 на порту 8333. Корзины `books`, `covers` и `exports`
заводятся заранее; у `exports` задано автоудаление через сутки — собранный
архив всегда можно построить заново.

**Keycloak** поднимается со своей базой и импортирует realm `bookcase` из
`keycloak/import`. Импорт происходит только при первом запуске: чтобы забрать
изменения в realm-файле, нужен `docker compose down -v`.

Предел размера книги — 1 ГБ, и он один и тот же для приёма и для разбора: файл, который взяли
на хранение, должен быть разобран, а не отвергнут на следующем шаге. Сканы в высоком разрешении
и толстые справочники доходят до сотен мегабайт — в корпусе, на котором это проверялось, самая
большая книга весит 250 МБ.

**storage** принимает книги потоком, считает за один проход хэш содержимого и контрольную сумму,
складывает файл в SeaweedFS под именем этого хэша и ведёт список владельцев. Одинаковые байты
не могут оказаться в двух объектах, а объект удаляется, только когда ушёл последний владелец.
Оттуда же собираются архивы — без пережатия.

**catalog** ведёт карточки: заводит их по разобранным метаданным, ищет по названию, автору,
серии и издательству, отбирает по темам, формату, языку, году, полке и подборкам и считает
перечни значений с числами. Постраничность идёт по ключу, а не по смещению. Он же выдаёт ссылки
на скачивание и заводит задачи выгрузки библиотеки.

**ingester** разбирает загруженные файлы. Формат определяется по содержимому, а не по расширению;
метаданные берутся из самого файла, а чего в нём нет — из имени, и у каждого поля запоминается,
откуда оно взялось. Работа идёт в фоне, через очередь: разбор занимает секунды и упирается
в процессор. Испорченный файл или документ Word получают отказ с причиной сразу, а недоступное
хранилище — повтор через отдельный топик.

**oauth2-proxy** играет роль BFF: сам проходит вход, держит сессию в Valkey,
браузеру отдаёт только `HttpOnly`-cookie, а наверх передаёт токен доступа
заголовком `X-Forwarded-Access-Token`. Запрос с готовым Bearer проходит мимо
сессии — это путь программных клиентов. Запросы по путям `/api/v1/files`
и `/api/v1/archives` уходят в `storage`, `/api/v1/ingestions` — в `ingester`,
`/api/v1/ingestions` — в `ingester`, а `/api/v1/books`, `/api/v1/collections`,
`/api/v1/themes` и `/api/v1/exports` — в `catalog`. Что не подошло, отвечает пустым 200:
там будет фронтенд.

Ссылки со встроенным пропуском (`…/download/…`) проходят мимо входа: пропуск проверяет сам
сервис — подпись, срок и то, на что он выписан. Живёт такая ссылка минуту: кто её получил,
тот скачает файл, и ограничить это иначе нечем — браузер при переходе по ссылке о себе
ничего не сообщает.

Ни в том, ни в другом случае прокси не решает, кто пользователь: токен целиком
проверяет сам сервис, а заголовок лишь говорит, где этот токен лежит.

**Prometheus и Grafana** собирают метрики. Цели сервисов, которые не подняты,
числятся недоступными — так и должно быть. В Grafana уже заведены источники данных
и два дашборда из `deploy/helm/platform/files/dashboards` — «сервисы» и «путь книги»;
файлы подключены томом, так что правка на диске видна после обновления страницы.

**Tempo** хранит трассы. Сервисы отправляют их по OTLP на `tempo:4318`; адрес задан
переменной окружения, и только поэтому запуск сервиса из среды разработки никуда не
стучится — без адреса отправитель не создаётся. Искать трассу удобнее всего по
идентификатору из журнала: он же и есть идентификатор трассы. В Grafana это раздел
Explore, источник данных Tempo, поиск по Trace ID.

## Пределы ресурсов

У каждого контейнера задан предел по памяти и процессорам, а у самих программ —
их собственные пределы: куча Kafka, доля памяти для Keycloak, `maxmemory`
у Valkey, `shared_buffers` у PostgreSQL, срок и размер хранения у Prometheus.
Без этого Java-процессы считают своей всю память машины, а Prometheus растёт,
пока есть диск. Суммарно стенд укладывается в 4 ГБ и на холостом ходу занимает
около двух.
